# 我装了 25 个 AI Skills 后，明白了一件事

> 一名终端安全工程师的实测：单个 AI Skill 改变不了什么，但 25 个 Skills 组成的工作流，**真的能替代一个团队**。

---

## 前言：我从 1 个 Skill 装到了 25 个

上周末，我花了两个小时做一件事：**把我常用的 AI 工具方法论系统化**。

结果：我装了 25 个 Skills，覆盖搜索、写作、编程、调试、设计、媒体、读书笔记 7 大场景。

两个月后回头看，**有一件事比"装 Skills"本身更重要**——

> **不是装得多，是用得对。单个 Skill 是螺丝刀，组合 Skills = 流水线。**

今天我把这套"个人 AI 工作流"完整公开，包括：

- 我用哪些 Skill
- 怎么组合它们
- 一个真实案例：从读书到公众号文章

## 02. 关键认知：Skills 是"工具腰带"，不是"prompt"

很多人误以为 Skills 就是好的 prompt。**完全不是**。

### Prompt 的特点
- 一次性、临时性
- 每次都要重新写
- 依赖人的表达

### Skill 的特点
- **可复用的工具调用**
- 装一次永远用
- AI 自己知道"什么场景用什么"

**比喻**：

> Prompt 像你跟实习生说"帮我查一下 X"——每次都要重新说。
>
> Skill 像你给实习生配了一台电脑 + 装好了软件——他自己会查。

**关键洞察**：

> **你装 Skills 的过程，就是在给 AI "配工具"的过程。**
>
> 你不可能把一个刚毕业的学生培训成资深工程师，但你可以**给他配一个好工具箱 + SOP**。

## 03. 怎么选 Skill？我用"四问法"

每装一个 Skill 前问自己：

1. **我每周会用吗？**（低于 1 次 = 不装）
2. **它能解决的具体场景是什么？**（含糊 = 不装）
3. **这个 Skill 是 1 个 tool 还是 1 套 system？**（system 优先）
4. **不装它，损失是什么？**（损失小 = 延后）

**用这四问筛 24 个候选 Skill，通常只装 1/3**。

## 04. 单 Skill vs Skill 组合：流水线思维

### 反例：手动跑单个 Skill

```
1. 打开微信读书 → 找今天的划线
2. 复制粘贴到 Notion
3. 让 AI 帮我总结
4. 复制到 WordPress
5. 复制到公众号
6. 复制到小红书
```

**6 步，每步 5 分钟 = 30 分钟/天 = 1.5 小时/周 = 78 小时/年**

### 正例：Skill 组合 + 脚本编排

```bash
~/.hermes/longxia/daily-deploy.sh
```

这一行命令**自动完成**：

1. `weread-skills-official` 拉今天的划线
2. AI 整理成 Markdown
3. `writing-expert-team` 改成 4 个平台版本
4. 同步到网站
5. 重新 build
6. 部署

**30 秒/天 = 3 小时/年**

**节省 75 小时/年 = 9 个工作日**。

## 05. 一个真实案例：从读书到公众号

**今天早上 7:53，我读了《Skills最系统手把手教程》**，划了 38 条线。

**30 分钟后**，这篇文章已经在你面前了。流程是这样的：

```
1. 微信读书划线（手动，7:53-7:55）
   ↓
2. weread-skills 自动拉划线 + 生成 Markdown
   ↓
3. AI 按 5 大主题重新归类（这不是按章节，是按"内容主题"）
   ↓
4. AI 写"行动建议"——"读完后你该做什么"
   ↓
5. AI 生成公众号草稿
   ↓
6. 同步到网站
   ↓
7. 部署上线
   ↓
8. 多平台分发：公众号 + 小红书 + 头条 + 知乎
```

**8 步，全程不到 30 分钟**。如果手动，至少 2 小时。

## 06. 我踩过的 3 个坑

### 坑 1：装太多

一开始我装了 40 多个 Skill。结果：

- **找 skill 的时间 > 用 skill 的时间**
- 互相冲突的 skill（写作的有 3 个）
- 维护成本高（更新、删掉冲突的）

**现在 25 个，每次升级都重新评估**。

### 坑 2：装"看起来有用"的

- `apple` skill：管理 Apple 设备 → 我用 Windows，装了从没用
- `smart-home`：智能家居 → 我家没智能家居
- `dogfood`：QA 测试 web app → 不做 QA

**"看起来酷"不等于"我用得上"**。

### 坑 3：忽视"工作流"思维

只装单个 skill = 你有一个工具箱
**组合 skill = 你有一条流水线**

**装第 26 个 skill 之前，先想想：能不能和已有的组合出新工作流**。

按使用频率从高到低：

### 🟢 阶段 1：必装（P0）

```

✅ AnySearch              # 搜索

```

**3 个就够 80% 的场景**。

### 🟡 阶段 2：按职业装（P1）

| 你的职业 | 推荐 |
|---------|------|
| 程序员 | `superpowers` + `plan` + `spike` + `tdd` |
| 安全/运维 | `systematic-debugging` + `nano-pdf`（处理报告） |
| 学生/研究 | `arxiv` + `ocr-and-documents` |
| 运营/营销 | `writing-expert-team` + `note-taking` |

**再加 3-5 个就够用**。

### 🔵 阶段 3：按兴趣装（P2）

- `architecture-diagram`（画图党）
- `humanizer`（去 AI 味）
- `powerpoint`（做 PPT）

**不急，用到再装**。

## 08. 评估 Skill 的"5 个问题"

每装一个 Skill 前问：

| # | 问题 | 答"是"=装 | 答"否"=不装 |
|---|------|----------|------------|
| 1 | 这周会用吗？ | ✅ | ❌ |
| 2 | 解决具体场景？ | ✅ | ❌ |
| 3 | 比已有功能强？ | ✅ | ❌ |
| 4 | 安装/运行安全？ | ✅ | ❌ |
| 5 | 不装损失大？ | ✅ | ❌ |

**5 个全 "是" 才装**。

## 09. 你的 25 个 Skills 不一定是我的 25 个

**重要**：

> **每个人的 Skills 库都不一样，取决于你的职业、习惯、需求**。

我的 25 个**仅供参考**。你的 25 个可能是：

- 设计师：`Figma 自动化` + `配色生成` + `图像处理`
- 销售：`CRM 操作` + `邮件模板` + `客户跟进`
- 学生：`论文检索` + `笔记整理` + `考试复习`

**关键是"装对不装多"**。

## 10. 怎么开始：今天就能做的 3 步

### 第 1 步：盘点你现有的 Skills

打开 `~/.hermes/skills/`，数一下你装了多少。**删掉 3 个月没用的**。

### 第 2 步：找 1 个工作流串起来

找到你每天做的**重复 3 步以上**的事，看能不能用 Skills 串。

比如：
- 读文章 → 摘要 → 写卡片 → 发布 = 4 个 skill 串
- 写代码 → 测 → 提 PR → 部署 = 5 个 skill 串

### 第 3 步：写一个"daily.sh"

把你的工作流写成脚本，每天跑一次。

**这是"组合 Skills"的最简单方式**。
