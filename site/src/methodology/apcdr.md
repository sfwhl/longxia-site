# 🎯 新型威胁快速分析与产品化闭环方法论

> **AI 时代真正有价值的能力，不是单纯会使用 AI，也不是只会分析某一个病毒样本，而是建立一套可重复执行的威胁研究与产品落地体系**
>
> 面对未知勒索病毒、攻击工具或新型攻击手法，能够快速完成样本验证、证据提取、攻击链还原、检测点提炼、处置方案设计，并将能力稳定落地到 EDR 产品中。
>
> **一句话定位**：
> 未知威胁快速研究与防护能力。

---

## 📊 最终形成的闭环

```
发现问题 → 构造实验 → 采集证据 → 还原攻击链 → 提炼检测点
   ↓
设计处置能力 → 工程落地 → 测试验证 → 运营复盘 → 知识沉淀
```

**核心**：每一步都有标准化输入和输出 → 可重复、可积累、可传承。

---

## 👥 一、人和 AI 的职责边界

### 人负责的核心工作（AI 不能替代）

- 判断当前问题是否具有真实安全风险
- 设计可信、可复现的实验环境
- 确认日志与行为之间的因果关系
- 判断哪些行为是攻击特征，哪些是普通软件行为
- 评估检测规则的误报和性能影响
- 决定能力应该落在哪个产品模块
- 判断阻断是否可能引发蓝屏、系统异常或业务中断
- 对最终方案的完整性和安全性负责

### AI 适合承担的工作（加速 + 扩大深度）

- 分析 Procmon、ETW、网络日志和目录差异
- 对比多个样本的共同特征
- 提取注册表、文件、进程和命令行行为
- 检索公开威胁情报、ATT&CK 技术和开源项目
- 生成调查脚本、解析程序和测试代码
- 生成 Windows C++ 核心代码框架
- 整理调研报告、设计方案和测试用例
- 帮助检查分析结论是否存在遗漏

### 协作模式

> **不是"让 AI 自动分析病毒"，而是：**
> **人负责提出正确问题和判断证据，AI 负责扩大分析深度并压缩交付周期。**

## 📋 二、新型威胁分析十步法

### 第一步：明确分析目标

**开始分析前必须回答 3 个问题**：

#### 1. 当前产品失效点是什么

举例：
- EDR 完全没有告警
- 有告警但未阻断
- 阻断发生在文件已经被加密之后
- 仅外网环境可以复现
- 仅管理员权限下可以执行
- 驱动层没有获取到关键行为
- 应用层检测链路存在延迟

#### 2. 本次分析需要回答什么（至少应包含）

- 样本如何启动
- 是否释放其他文件
- 是否创建子进程
- 是否提权或绕过权限
- 如何发现目标文件
- 如何加密文件
- 是否删除原文件
- 是否修改文件扩展名
- 是否留下勒索信
- 是否终止安全软件或业务进程
- 是否删除备份和卷影副本
- 是否建立网络连接
- 是否依赖远程密钥
- 是否具备横向传播能力
- **当前 EDR 为什么没有检测到**
- **可以在哪些阶段进行检测或阻断**

#### 3. 定义最终交付物

**固定两份文档**：
1. 《攻击手法分析调研报告》
2. 《针对性检测与处置方案设计》

> **避免分析过程中只有零散结论，没有形成可进入研发流程的完整输入。**

---

### 第二步：建立隔离、可信、可复现的实验环境

#### 1. 环境要求

- 使用独立虚拟机
- 禁止桥接公司网络
- 使用快照恢复
- 准备**内网、外网、断网三种环境**
- 记录操作系统版本和补丁信息
- 记录样本哈希值
- 统一测试账号和权限
- 统一被加密文件集
- 统一执行方式
- 统一日志工具配置

#### 2. 建议准备三组实验

| 实验 | 目的 |
|------|------|
| **断网实验** | 判断样本是否可以离线完成加密 · 判断是否依赖远程密钥 · 排除网络交互对行为的影响 |
| **内网实验** | 分析文件加密行为 · 判断是否进行局域网扫描 · 判断是否访问共享目录 · 判断是否存在横向移动 |
| **外网实验** | 分析 DNS、HTTP、HTTPS、TCP、UDP 外联 · 判断是否下载配置或密钥 · 判断是否上传主机信息 · 判断是否存在 C2 通信 |

#### 3. 每次实验必须记录

```
样本路径 / SHA256 / 执行时间 / 执行权限 / 系统版本 /
网络环境 / EDR 状态 / 测试文件数量 / 测试前快照 /
测试后结果 / 日志文件路径
```

---

### 第三步：建立干净基线和差异对比

> **单独观察样本执行日志通常噪声很大，必须使用基线对比。**

#### 1. 基线实验

在同一环境中，**不执行样本**，仅完成：
- 开机
- 登录
- 等待相同时间
- 执行相同的日志采集工具

得到系统正常运行基线。

#### 2. 差异分析对象

对比样本执行前后：

- 文件目录变化
- 文件内容变化
- 文件扩展名变化
- 文件头变化
- 文件大小变化
- 注册表变化
- 服务变化
- 计划任务变化
- 进程树变化
- 模块加载变化
- 网络连接变化
- 卷影副本变化
- 日志清理行为
- 安全产品状态变化

#### 3. 文件加密结果对比

针对"加密前原文件"和各样本执行后的结果：

- 哪些扩展名被加密
- 哪些目录被跳过
- 系统目录是否被跳过
- 文件头部是否被覆盖
- 文件尾部是否附加数据
- 是否全量加密
- 是否分段加密
- 大文件和小文件策略是否不同
- 是否保留原始文件
- 是否执行"写新文件 → 删除原文件 → 重命名"
- 是否原地覆盖
- 是否统一添加扩展名
- 不同样本的加密结果是否一致

**这一步直接决定检测点**：
- 高密度文件写入
- 批量重命名
- 文件熵变化
- 原文件删除
- 特定文件头修改
- 扩展名批量变化
- 文件遍历行为

---

### 第四步：多维度采集行为证据

> **不要只依赖 Procmon。单一工具只能看到攻击链的一部分。**

#### 1. 文件系统行为

**重点关注**：
- QueryDirectory / CreateFile / ReadFile / WriteFile
- SetRenameInformationFile / SetDispositionInformationFile / DeleteFile
- 文件扩展名变化 / 勒索信创建 / 高并发文件访问
- 短时间访问多个用户目录

**数据源**：
- Minifilter / ETW File I/O / USN Journal
- Procmon / 文件系统回调 / 应用层目录监控

#### 2. 进程行为

**重点关注**：
- 样本父进程 / 子进程 / 命令行
- 提权方式 / 是否创建隐藏进程 / 是否注入其他进程
- 是否终止安全进程 / 是否调用系统工具
- 是否使用 PowerShell、WMI、cmd、rundll32 等

**数据源**：
- PsSetCreateProcessNotifyRoutineEx / ETW Kernel Process
- WMI / 进程句柄监控 / 命令行采集 / CreateProcess 审计

#### 3. 注册表行为

**重点关注**：
- Run、RunOnce / 服务注册表 / Shell 修改
- 文件关联 / SafeBoot / Defender 配置 / UAC 配置
- 系统恢复相关配置 / 持久化位置

**数据源**：
- CmRegisterCallbackEx / ETW Registry / Procmon

#### 4. 系统破坏行为

**重点关注**：
- 删除卷影副本 / 停止备份服务 / 修改启动配置
- 清空事件日志 / 关闭防火墙 / 禁用 Defender / 禁用恢复环境
- 删除备份目录 / 终止数据库和办公软件

**重点命令**：
- `vssadmin` / `wbadmin` / `bcdedit` / `wevtutil`
- `sc` / `net stop` / `taskkill` / `powershell` / `wmic`

**检测要点**：
- 不能只检测完整命令字符串
- 应同时识别：命令行参数组合 / 对应系统 API / WMI 调用 / COM 调用 / 直接调用底层接口的绕过方式

#### 5. 网络行为

**重点分析**：
- DNS 查询 / 目标 IP / 目标端口 / TLS SNI / HTTP Host / URL 路径
- JA3/JA4 指纹 / 首次外联时间
- 加密前还是加密后外联 / 是否周期性通信
- 是否上传主机标识 / 是否请求密钥
- 断网后行为是否变化

**数据源**：
- ETW DNS / WFP / WinHTTP/WinINet 监控
- Sysmon / PCAP / Procmon 网络事件

**网络结论必须区分**：
- 样本必需外联 / 可选外联 / 失败重试
- 环境探测 / 遥测上报 / 密钥交换 / C2 通信 / 完全无网络行为

**重要提醒**：没有发现外联 ≠ 没有网络模块。可能存在：
- 域名失效 / C2 下线 / 沙箱规避
- 时间触发 / 地域限制 / 环境检查未通过
- 仅特定样本版本支持联网

---

### 第五步：还原完整攻击链

将离散行为组合为有因果关系的攻击链。

#### 14 个阶段

```
1. 初始执行
2. 环境检查
3. 权限判断
4. 防护规避
5. 持久化
6. 进程或服务终止
7. 备份破坏
8. 文件发现
9. 文件加密
10. 文件重命名
11. 勒索信投放
12. 网络通信
13. 清理痕迹
14. 横向传播
```

#### 每个阶段记录 4 项内容

| 项目 | 内容 |
|------|------|
| 行为 | 样本具体做了什么 |
| 证据 | 日志、文件、注册表或网络证据 |
| 技术实现 | 可能使用的 API 或系统机制 |
| **防护机会** | 可以在哪个阶段检测或阻断 |

---

### 第六步：将行为映射为 TTP，而不是只记录 IOC

#### IOC（短期、易绕过）
- 样本哈希 / 文件名 / 域名 / IP
- 注册表路径 / 勒索信名称 / 加密扩展名

#### TTP（长期、稳定、可泛化）
- 批量遍历用户文件
- 高频读写和重命名
- 删除卷影副本
- 停止备份服务
- 终止安全软件
- 清理日志
- 修改启动项
- 加密共享目录
- 短时间修改大量不同类型文件

**两层能力都要做**：
- **IOC 层**：用于快速上线应急规则
- **行为层**：用于形成长期、稳定、可泛化的产品能力

## 🎯 四、检测点提炼方法

### 1. 检测点选择原则（5 维评估）

| 维度 | 问题 |
|------|------|
| **区分度** | 正常软件是否也会执行 |
| **提前量** | 能否在大量文件被加密前触发 |
| **稳定性** | 样本变种是否容易绕过 |
| **性能** | 是否适合终端长期运行 |
| **可处置性** | 触发后能否安全阻断 |

### 2. 四级检测体系

#### 一级：明确恶意行为

- 勒索样本哈希命中
- 已知恶意域名
- 已知勒索信
- 已知加密扩展名
- 已知恶意证书

→ 适合**直接告警或阻断**

#### 二级：高风险系统行为

- 删除卷影副本
- 禁用恢复功能
- 关闭安全服务
- 批量终止业务进程
- 清空日志

→ 适合**结合进程信誉、签名和父进程判断**

#### 三级：勒索行为模型

- 短时间访问大量文件
- 文件熵显著升高
- 大量文件被重命名
- 多种扩展名被连续修改
- 原文件删除后生成新文件
- 多目录并发写入

→ 适合**使用滑动窗口和风险评分**

#### 四级：攻击链关联

同一进程在较短时间内连续发生：
1. 查询大量目录
2. 删除卷影副本
3. 终止备份服务
4. 高频修改文件
5. 创建勒索信

→ **比单点规则更稳定**

## 📊 五、勒索行为评分模型

> **不要依赖单个事件直接判定勒索，而是维护进程级风险状态。**

### 评分示例

| 行为 | 分值 |
|------|------|
| 删除卷影副本 | 40 |
| 禁用恢复功能 | 30 |
| 终止备份服务 | 25 |
| 1 分钟修改超过 100 个文件 | 25 |
| 多种扩展名文件被连续改写 | 20 |
| 文件平均熵明显上升 | 20 |
| 批量重命名文件 | 15 |
| 创建勒索信 | 30 |
| 修改多个磁盘目录 | 15 |
| 访问网络共享目录 | 15 |
| 无签名未知程序 | 10 |
| 从临时目录或下载目录执行 | 10 |

### 处置阈值

| 分数 | 动作 |
|------|------|
| 30 | 记录增强日志 |
| 50 | 高危告警 |
| 70 | 暂停进程并进行确认 |
| 90 | 终止进程、隔离文件并断网 |

> **实际分值必须基于样本测试和白样本压测调整。**

## 🚨 六、针对性处置策略

### 1. 处置原则

**按照"损害最小化"和"证据保留"设计，不能简单执行进程终止。**

**推荐顺序**：

```
1. 暂停可疑进程
2. 阻止新的文件写入
3. 阻止新进程创建
4. 阻断网络
5. 保存现场证据
6. 终止恶意进程
7. 隔离样本及释放文件
8. 恢复被篡改配置
9. 尝试恢复文件
10. 上报告警和运营数据
```

### 2. 为什么优先暂停进程

**直接终止进程可能导致**：
- 文件正处于写入中
- 关键证据丢失
- 子进程继续执行
- Watchdog 进程重新拉起
- 样本执行异常清理逻辑

**暂停进程后**，可以先完成：
- 进程树分析 / 文件句柄采集 / 网络连接采集
- 内存信息保留 / 相关子进程定位

### 3. 核心处置能力

#### 进程处置
- 暂停进程 / 终止进程树 / 禁止恶意进程重启
- 隔离可执行文件 / 阻止子进程创建

#### 文件处置
- 阻止继续写文件 / 备份被修改文件
- 隔离勒索样本 / 记录被影响文件清单
- 尝试利用备份或卷影恢复

#### 网络处置
- 阻断进程网络 / 阻断恶意 IP 和域名
- 临时隔离终端 / 保留管理通道和 EDR 上报通道

#### 系统恢复
- 恢复安全服务 / 恢复备份服务
- 恢复 Defender 配置 / 恢复启动配置
- 检查卷影副本 / 删除恶意持久化项

## 💻 七、Windows C++ 工程落地框架

### 1. 数据采集层

**采集内容**：
- 进程创建 / 文件读写 / 文件重命名 / 文件删除
- 注册表修改 / 服务修改 / 命令行
- 网络连接 / DNS 查询

**技术选择**：
- 内核回调 / Minifilter / WFP / ETW / 应用层周期扫描

### 2. 事件标准化层

```cpp
struct SecurityEvent {
    uint64_t timestamp;
    uint32_t processId;
    uint32_t parentProcessId;
    EventType type;
    std::wstring processPath;
    std::wstring targetPath;
    std::wstring commandLine;
    uint64_t fileSize;
    double fileEntropy;
    std::wstring remoteIp;
    uint16_t remotePort;
};
```

### 3. 进程画像层

```cpp
struct ProcessRiskContext {
    uint32_t processId;
    uint64_t startTime;
    uint32_t readFileCount;
    uint32_t writeFileCount;
    uint32_t renameFileCount;
    uint32_t deleteFileCount;
    uint32_t affectedDirectoryCount;
    uint32_t affectedExtensionCount;
    bool deletedShadowCopy;
    bool disabledRecovery;
    bool stoppedBackupService;
    bool createdRansomNote;
    int riskScore;
};
```

### 4. 滑动窗口检测

```cpp
void OnFileEvent(const SecurityEvent& event) {
    ProcessRiskContext& ctx = GetProcessContext(event.processId);
    UpdateFileStatistics(ctx, event);
    RemoveExpiredEvents(ctx, GetCurrentTime());
    ctx.riskScore = CalculateRiskScore(ctx);
    
    if (ctx.riskScore >= kBlockThreshold) {
        TriggerRansomwareResponse(ctx);
    } else if (ctx.riskScore >= kAlertThreshold) {
        ReportHighRiskProcess(ctx);
    }
}
```

### 5. 风险评分

```cpp
int CalculateRiskScore(const ProcessRiskContext& ctx) {
    int score = 0;
    if (ctx.deletedShadowCopy) score += 40;
    if (ctx.disabledRecovery) score += 30;
    if (ctx.stoppedBackupService) score += 25;
    if (ctx.writeFileCount >= 100) score += 25;
    if (ctx.renameFileCount >= 50) score += 15;
    if (ctx.affectedExtensionCount >= 10) score += 20;
    if (ctx.createdRansomNote) score += 30;
    return score;
}
```

### 6. 联动处置

```cpp
void TriggerRansomwareResponse(const ProcessRiskContext& ctx) {
    SuspendProcess(ctx.processId);
    BlockProcessFileWrite(ctx.processId);
    BlockProcessNetwork(ctx.processId);
    CollectProcessEvidence(ctx.processId);
    CollectOpenFileHandles(ctx.processId);
    CollectNetworkConnections(ctx.processId);
    TerminateProcessTree(ctx.processId);
    QuarantineExecutable(ctx.processId);
    RestoreSecurityConfiguration();
    ReportRansomwareIncident(ctx);
}
```

## ✅ 八、验证方案

### 1. 恶意样本测试

至少验证：
- Sorry 不同样本
- 不同权限
- 断网 / 内网 / 外网环境
- 不同文件数量 / 不同文件类型
- 不同磁盘
- 网络共享目录
- 系统重启后的行为

### 2. 白样本测试

**必须测试容易产生类似行为的软件**：

| 类别 | 软件 |
|------|------|
| 压缩 | 压缩 / 解压软件 |
| 备份 | 备份软件 |
| 同步 | 文件同步工具 |
| 编译 | 编译工具 |
| 数据 | 数据库 |
| 游戏 | 大型游戏更新 |
| 文档 | 文档批量转换 |
| 媒体 | 图片批处理 |
