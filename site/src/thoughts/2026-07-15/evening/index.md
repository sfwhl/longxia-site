## 🔬 拆解：为什么是"Harness"而不是"AI 更聪明"

### ❌ 旧范式：让 AI 更聪明

```
2018-2024 的主流思路：

"AI 写代码不够好 → 把模型做大 → 写代码更好"

问题：模型从 GPT-3 → GPT-4 → Claude 3 → Claude 3.5
      能力在涨，但人类审核速度没涨
      → 审核瓶颈反而更严重
```

### ✅ 新范式：让 AI 能"自证"

```
2024-2026 转折点（Claude Code、Cursor Composer、Cognition Devin）：

"AI 已经够聪明 → 关键是让它做的事可被自动验证"

核心转变：
- 不是 AI → 更聪明的代码
- 而是 AI → 可验证的代码 + 验证机制本身

人类角色：
- 从 "写代码的人" → "设计验证系统的人"
```

## 🏗️ Harness 到底是什么

**Harness = 让 AI Agent 工作的"约束系统"**，4 个核心组件：

### 1️⃣ 设计约束（Constraints）

**不让 AI 做不该做的事**——通过规则文件：

```markdown
# 项目规则（CLAUDE.md 或 .cursorrules）

## 禁止
- 不要碰 .env / secrets 文件
- 不要直接 push 到 main
- 不要重命名 public API
- 不要装新依赖（要装先问）

## 必须
- 每次改动前先跑测试
- 改动后跑 lint + 类型检查
- 报告改动了哪些文件 + 改了哪几行
- API 改动必须更新对应文档
```

**效果**：80% 明显违规在源头被挡。

### 2️⃣ 测试体系（Verification）

**让 AI 写的代码能被自动验证**：

| 测试类型 | 谁写 | 谁能跑 |
|---------|------|--------|
| 单元测试 | AI 写 + 人类审 | AI 自动 |
| 集成测试 | 人类定义边界 + AI 写 | AI 自动 |
| 端到端 | 人类定义场景 | AI 自动 |
| 性能测试 | AI 写 | AI 自动 |

**关键**：**测试不是事后检查，是 AI 写代码时的"指南针"**。

### 3️⃣ 反馈闭环（Feedback Loop）

**让 AI 能从错误中学**：

```
AI 写代码
   ↓
自动跑测试 → 失败
   ↓
AI 看错误信息 → 自己改
   ↓
再跑测试 → 通过
   ↓
输出 diff 给人类
```

**Anthropic 的设计**：Claude Code 默认会**自己 debug 最多 N 轮**，N 轮失败才停下问人。

### 4️⃣ Agent 工作流（Workflow）

**多 AI 协作的流水线**：

```
┌─────────────────────────────────┐
│  AI #1：理解需求，写代码         │
└─────────────────────────────────┘
         ↓
┌─────────────────────────────────┐
│  AI #2：审 AI #1 的代码          │
│  - 找 bug / 安全 / 性能 / 风格   │
└─────────────────────────────────┘
         ↓
┌─────────────────────────────────┐
│  AI #3：对比 AI #1 和 AI #2      │
│  - 标出分歧点                   │
└─────────────────────────────────┘
         ↓
┌─────────────────────────────────┐
│  人类：只处理 AI 之间的分歧      │
└─────────────────────────────────┘
```

**关键洞察**：**AI 之间的分歧，是人类最值得花时间的地方**。

## 📊 未来 3-5 年工程师的角色演变

### 旧角色的消亡

```
❌ "我能 1 天写 500 行代码"     → 不再是优势
❌ "我熟悉所有 API"             → AI 知道得更全
❌ "我能 debug 任何 bug"        → AI debug 比你快
❌ "我能写精巧的算法"           → AI 写得更好
```

### 新角色的崛起

| 新能力 | 含义 | 对应你的感悟 |
|--------|------|-------------|
| **设计约束** | 写 CLAUDE.md / 项目规则 | = "如何让 AI 在边界内自由" |
| **测试体系** | 设计可验证的接口 | = "5 问自检的工程版本" |
| **反馈闭环** | 让 AI 从错误中学 | = "复盘 + 版本迭代" |
| **Agent 工作流** | 多 AI 协作流水线 | = "Skill 库 + CoT" |

**这些能力全部对应你今天感悟的方法论**——**你不是学新东西，是把你已经领悟的方法论应用到工程领域**。

### 共同点

**所有头部团队都在押注**：

```
未来 5 年最有价值的，不是更大的模型
而是更好的 Harness：
- 工具生态（让 AI 能做的事更结构化）
```
